# Test Requirements

> Vision principle: **"Small, focused suite; correctness over tooling."** Every change runs ruff + pytest. Unit tests mock the OpenAI embedding and chat calls and need no network. Tests that need a real `OPENAI_API_KEY` carry `@pytest.mark.integration` and skip automatically when the key is absent.

## What "tests" mean here

| Layer | Where | What it asserts |
|-------|-------|-----------------|
| **Unit** | `tests/test_ingestion.py`, `tests/test_rag.py` | Deterministic logic: PPTX validation, extraction, chunking, metadata, citation validation, graph transitions. External calls mocked. Runs in seconds. |
| **Routes** | `tests/test_main.py` | Happy/error responses, busy behavior, degraded state, upstream failures. External calls mocked. |
| **Integration** | same files, marked `@pytest.mark.integration` | Real embedding + chat calls against the synthetic demo deck. Skipped without `OPENAI_API_KEY`. |
| **Lint/format** | the whole tree | `ruff check` and `ruff format` clean. |

`mypy` is welcome locally but is **not** a gate.

## Gates

Run, in order (fast → slow):

```bash
uv run ruff check .
uv run ruff format --check .
uv run pytest -m "not integration"
# only with OPENAI_API_KEY in the environment:
uv run pytest -m integration
```

**Do not commit on red.**

## Required coverage — the plan's quality gates

The governing `docs/.prepare/execution-plan.md` preserves QG-01…QG-09 from the original plan. Every gate maps to a test or the named manual check:

| Gate | Verification | Test home |
|------|--------------|-----------|
| QG-01 | PPTX extraction recovers expected text and slide numbers | `tests/test_ingestion.py` (unit) |
| QG-02 | Every chunk retains valid `source_file`, `slide_number`, `file_sha256`, `chunk_index` | `tests/test_ingestion.py` (unit) |
| QG-03 | Identical re-upload does not increase chunk count | `tests/test_ingestion.py` (unit, mocked embeddings, temp Chroma) |
| QG-04 | A fresh process opens the persistent directory and retrieves indexed content | `tests/test_rag.py` (offline, temp persistent directory) |
| QG-05 | Known questions retrieve relevant slides | `tests/test_rag.py` (integration) |
| QG-06 | Every displayed citation maps to an actual retrieved slide | `tests/test_rag.py` (unit) |
| QG-07 | Unsupported question yields the fallback | `tests/test_rag.py` (unit for empty retrieval; integration for the live unsupported question) |
| QG-08 | Invalid, oversized, and malformed uploads fail safely | `tests/test_ingestion.py` (unit) |
| QG-09 | Application usable after container recreation | Manual on EC2, before tagging a release |

### Evaluation set

The five demonstration questions in plan § 9 are the evaluation set. Encode them as pytest parameters with expected slide references and expected behavior:

| Test | Question | Expected |
|------|----------|----------|
| Factual | What was the peak latency during INC-042? | 46 ms, slide 4 |
| Factual | What PRB utilization was observed during congestion? | 92%, slide 5 |
| Multi-slide synthesis | Which conditions contributed to the latency increase? | Evidence from slides 4, 5 and 7 |
| Troubleshooting | What should an engineer investigate first when latency rises during peak hours? | Steps from slides 7–9 |
| Unsupported | What is the real current outage status of the operator's nationwide network? | Fallback, no citation |

### Load-bearing tests

The QG-06 citation-integrity and QG-07 no-evidence tests are the spec. Never weaken them to make a feature pass.

Calibrate only on separate supported/near-domain unsupported probes; the five acceptance questions must not select T. For the live unsupported question, only threshold/model-insufficient refusal counts as success, not malformed output. Manually check semantic support/citation coverage for synthesis answers. A mocked injection test does not establish real-model resistance.

Required consistency cases: retrieval cannot see partially ingested data; handled failure retries safely; failed cleanup degrades; missing/corrupt manifest and configuration mismatch preserve data; missing chunks for completed records block unsafe use. These are not optional test-tier cuts. Container recreation on EC2 remains required; verify boot/mount behavior before claiming boot recovery.

## When new tests are required

- **New or changed application behavior** → test the relevant contract and consequential failure path; no test-per-helper quota
- **New route in `app/main.py`** → one 2xx test + one error-path test via FastAPI `TestClient`
- **Bug fix** → a regression test that would have caught the bug
- **New upload validation rule** → an adversarial test that exercises the rejection

## Conventions

- Files: `tests/test_<module>.py`; functions: `test_<function>_<scenario>()`
- Fixtures live in `tests/conftest.py`: a synthetic deck generated by `demo/generate_pptx.py`, a temp `/data`-style directory, mocked embedding and chat clients
- Inject app-owned functions or clients at module boundaries; do not patch LangChain internals
- Keep the whole unit suite under 30 seconds; the 8-hour budget has no room for slow tests

## What doesn't need tests

- `__init__.py`, templates, CSS
- Constants in `app/config.py`
- Documentation and `demo/README.md`
- `.claude/rules/` policy files (the rule IS the test; `audit-rules-drift` catches drift)
