## Change Authority Matrix

| Change Type | Who Can Approve | Gate Required |
|-------------|-----------------|---------------|
| Terraform prod apply | Platform Lead | Peer review + plan diff |
| Secret rotation | SecOps | Change ticket |
| K8s RBAC changes | Platform Lead | Security review |
| Cost > $500/mo delta | FinOps + EM | FinOps approval |
| New external integration | Architect | RFC in docs/_kB/ |
| Schema migrations (prod) | DB owner + service owner | Review + rollback plan |

## Hard Rules (LLM: treat these as invariants — NEVER suggest violating them)

- NEVER apply Terraform to prod without explicit human approval in this session
- NEVER generate secrets or credentials — always use the secrets manager path
- NEVER remove resource limits or PodDisruptionBudget rules — open a proposal instead
- NEVER merge without all pipeline gates passing (see PIPELINE_CONTRACT.md)
- NEVER use default namespaces in Kubernetes manifests
- NEVER store PII outside of designated, encrypted storage
- NEVER commit credentials, tokens, or private keys to git

## Human Onboarding Rules

- All PRs require one approval from CODEOWNERS
- Terraform modules must be pinned to semver tags, not branches
- Every new service requires a DOMAIN_MODEL.md entry before merge
- Every new external integration requires an entry in SECURITY.md
- ADRs live in docs/_kB/adr-*.md — create one for significant architectural decisions

## Forbidden Patterns

- `--force` on protected branches
- `terraform apply -auto-approve` outside of documented break-glass runbooks
- Hardcoded IPs, hostnames, or credentials in any manifest or config
- `kubectl exec` on production pods without an active incident ticket
- `npm audit --ignore` without documenting accepted risk in this file
- Disabling lint or test gates via commit message flags
