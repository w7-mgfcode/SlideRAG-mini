## Required Resource Requests & Limits (LLM: enforce for EVERY workload manifest)

| Class | CPU Request | CPU Limit | Memory Request | Memory Limit |
|-------|-------------|-----------|----------------|--------------|
| API service | 100m | 500m | 128Mi | 512Mi |
| Worker | 250m | 1000m | 256Mi | 1Gi |
| Batch job | 500m | 2000m | 512Mi | 2Gi |
| Sidecar | 10m | 50m | 32Mi | 64Mi |
| Init container | 50m | 200m | 64Mi | 256Mi |

**NEVER** omit resource requests. **NEVER** set CPU limit to 0 or omit it.

## Required PodDisruptionBudget Rules

- Every Deployment with `replicas >= 2` MUST have a PDB in the same namespace
- Non-critical services: `minAvailable: 1`
- Critical path services: `minAvailable: 50%`
- **NEVER** delete or reduce a PDB without Platform Lead approval (see RULES.md)

## Required HPA Configuration

- Every production Deployment MUST have HPA
- `minReplicas: 2` minimum (single replica = SPoF, prohibited in prod)
- `maxReplicas`: defined per service class below
- Scale metric: CPU utilization OR custom Prometheus metric (not both)

| Class | Min Replicas | Max Replicas | Scale-Up Trigger | Scale-Down Delay |
|-------|-------------|-------------|-----------------|-----------------|
| Critical API | 3 | 20 | CPU > 60% | 300s |
| Standard API | 2 | 10 | CPU > 70% | 180s |
| Worker | 1 | 5 | Queue depth > 100 | 120s |

## Required Probe Configuration

| Probe | Required For | Minimum Config |
|-------|-------------|---------------|
| Liveness | All long-running workloads | `initialDelaySeconds: 30, periodSeconds: 10` |
| Readiness | All services | `initialDelaySeconds: 5, periodSeconds: 5` |
| Startup | Slow-starting apps (JVM, large models) | `failureThreshold: 30, periodSeconds: 10` |

**NEVER** use a liveness probe path that has side effects (writes, state mutations).
**NEVER** set `liveness.initialDelaySeconds` < `readiness.initialDelaySeconds`.

## Security Baseline

```yaml
# Required for all non-privileged workloads
securityContext:
  runAsNonRoot: true
  runAsUser: 1000
  readOnlyRootFilesystem: true
  allowPrivilegeEscalation: false
  capabilities:
    drop: ["ALL"]
```

- `privileged: true` requires explicit RULES.md exception + Security review
- `hostNetwork: true` requires Security review
- `imagePullPolicy: Always` is FORBIDDEN in prod — use image digest pinning

## Anti-Patterns (LLM: flag these in review and refuse to generate them)

| Pattern | Problem | Correct Approach |
|---------|---------|-----------------|
| `resources: {}` | Missing resource limits — node OOM risk | Add class-appropriate limits from table above |
| `replicas: 1` without comment | Single point of failure in prod | Set `minReplicas: 2` or add justification comment |
| `imagePullPolicy: Always` | Non-deterministic deploys, registry dependency | Pin to image digest: `image: app@sha256:...` |
| `hostNetwork: true` | Bypasses network policy | Use ClusterIP service + proper DNS |
| No liveness probe | K8s can't detect deadlocks | Add probe per table above |
| No readiness probe | Traffic routed to unready pods | Add probe per table above |
| No PDB | Full outage during node drain | Add PDB per rules above |
