## Required Stages (LLM: these are NOT optional — never suggest skipping them)

| Stage | Blocking | On Fail | Runs On |
|-------|---------|---------|---------|
| lint + format validate | YES | Block merge | Every PR push |
| unit tests | YES | Block merge | Every PR push |
| security scan (Trivy/Checkov) | YES | Block on CRITICAL | Every PR push |
| build + tag artifact | YES | Block merge | Merge to main |
| deploy: staging | YES | Block prod | Merge to main |
| smoke test: staging | YES | Block prod | Post-staging deploy |
| deploy: prod | YES | Rollback trigger | Manual approval only |
| post-deploy test: prod | NO | Alert only | Post-prod deploy |

**NEVER** add a stage that can be skipped via a commit message flag in the prod path.
**NEVER** merge if any blocking stage is in a failed state — including hotfixes.

## Merge Conditions (ALL must be true before merge)

- [ ] All blocking CI stages: GREEN
- [ ] At least 1 CODEOWNER approval
- [ ] No unresolved review comments
- [ ] Branch is up-to-date with main
- [ ] Security scan: 0 CRITICAL findings

## Failure Gates

| Condition | Action |
|-----------|--------|
| Unit test coverage < 80% | Block merge |
| Trivy CRITICAL vuln found | Block merge + notify #security |
| Staging smoke test fails | Block prod deploy + create incident ticket |
| Prod deploy fails | Auto-rollback + page #oncall |
| Prod smoke test fails | Auto-rollback + page #oncall |
| Cost estimation > $500/mo delta | Require FinOps approval before apply |

## Secret Usage Model

- Secrets **NEVER** in env vars committed to git
- Secrets injected at runtime via ExternalSecrets → {AWS Secrets Manager / Vault / GCP Secret Manager}
- CI secrets (KUBECONFIG, cloud credentials) stored in CI secret store only
- Secret naming convention: `{project}/{environment}/{service}/{key}`
- Rotation: automated via RUNBOOKS.md#secret-rotation — **NEVER** manual in pipeline

## Artifact Contract

| Artifact | Produced By | Consumed By | TTL | Naming |
|----------|------------|------------|-----|--------|
| Docker image | build stage | deploy stages | 30 days | `{service}:{sha7}` |
| Helm package | build stage | deploy stages | 90 days | `{chart}-{semver}` |

| Terraform plan | plan stage | apply stage | 24 hours | `{sha}-tfplan` |

## Environment Promotion Rules

```
feature/*   → (auto)     → staging  (per PR, ephemeral env)
main        → (auto)     → staging  → (manual approval) → prod
hotfix/*    → (direct)   → prod     (requires SEV1 incident ticket number)
release/N.x → (auto)     → staging  → (approval)        → prod
```

**NEVER** deploy `hotfix/*` to prod without an active incident ticket number in the PR.

## Pipeline Configuration Standards

```yaml
# Required for all production pipelines
timeout-minutes: 30           # Hard timeout — never omit
concurrency:
  group: ${{ github.ref }}
  cancel-in-progress: true    # Cancel stale runs on new push

# Required for all deploy steps
environment: production       # Enables approval gates in GitHub Environments
```

## Rollback Procedure

1. Detect failure (automated via post-deploy test or alert)
2. Trigger rollback: `{helm rollback {release} || kubectl rollout undo}`
3. Confirm rollback complete: `kubectl rollout status`
4. Page #oncall if SEV1/SEV2
5. Open incident ticket with timeline
6. Run post-mortem within 48 hours for SEV1
